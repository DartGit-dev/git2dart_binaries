Defect and evidence

The aggregate validator accepts all required scopes even when every proof has empty inventory and versions, a null attestation, and no cryptographic connection to the assembled payload. Root cause state: confirmed.

Evidence: deterministic local reproduction, W002 semantic regression, .github/scripts/platform_release_proof.py:validate, and build_package.yml:721-722.

Chosen strategy

Direct correction. There is one confirmed causal path and one narrow, discriminating repair: validate a complete proof schema against the actual final release payload before subsequent release gates. A multi-agent debate is not recommended because there are no competing root-cause explanations; it would not reduce the release-boundary risk beyond the two approval gates.

Mandatory review follow-up

Independent review rejected the first Gate 2. The producer can emit an empty successful-linkage diagnostic that the aggregate validator rejects, and arbitrary non-empty attestation maps still qualify. The corrective sequence keeps CHG-001 through CHG-003 intact: first add tests for producer-to-validator compatibility and strict platform attestation semantics, then apply only the smallest validator repair required to turn those tests green.

Evidence: independent review rejection. No spec verdict or package closure is available until the corrective Gate 2 and a new independent review approve.
