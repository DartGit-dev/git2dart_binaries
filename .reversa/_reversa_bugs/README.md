# Reversa Bug Registry

> Generated by Reversa on 2026-08-16. This file is the bug-registry contract for this project.
> Source of truth: each `<context>/bugs/<ID>/bug.md`. Everything under `generated/` is a regenerable projection.

## Project configuration

```yaml
closure_policy: package
control_mode: gated
```

- `closure_policy` defines what completion requires. The user selected `package` on 2026-08-16:
  - `local-software`: passing regression tests plus a specification verdict
  - `package`: the previous conditions plus merge and publication of a corrected version, including required backports
  - `production-service`: the previous conditions plus deployment and an observation window without recurrence
- `control_mode: gated`: read-only inspection and diagnosis may proceed, but bug promotion, tests, code changes, effective-spec changes, external harness access, and destructive operations require their defined gates.

## Structure

Bugs are grouped by context, meaning a feature, module, or use case. A context directory is created only when an inspection or bug actually produces artifacts.

```text
_reversa_bugs/
|-- README.md
|-- taxonomy.yaml
`-- <context>/
    |-- bugs/BUG-<date>-<suffix>-<slug>/
    |   |-- bug.md
    |   `-- evidence/
    |-- inspections/<inspection>/
    `-- generated/
```

## Lifecycle

`status`: `open` to `active` to `resolved`. The `phase` field refines active work. Blocking is a condition, never a status. Every closure records a resolution kind.

When the closure policy is satisfied, the bug receives `DONE.md` and becomes read-only. A recurrence is recorded as a new bug with a `regression-of` relation.

## Traceability rule

Every bug must identify:

1. The effective specification section that defines expected behavior, or the `spec-gap` label.
2. Affected code and, after investigation, evidence-backed root cause.
3. Reproduction and regression tests.

A bug cannot be resolved as fixed while its specification trace, confirmed root cause, or regression tests are empty.

## Agent protocol

1. `/reversa-debugger` registers and never fixes.
2. `/reversa-debugger-fix` uses separate approval gates for tests and code changes.
3. Original specifications are not edited by the bug workflow. A behavior change becomes a versioned addendum.
4. Restricted security bugs are excluded from generated views and external harnesses.
5. Relations and root causes retain explicit epistemic status.

## Conventions

- Canonical ID: `BUG-<YYYYMMDD>-<suffix>`.
- References use the canonical ID.
- Evidence belongs under `evidence/`, not as large inline logs.
- The complete bug schema is defined in the local Reversa debugger references.
