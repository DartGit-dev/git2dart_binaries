Correction plan: BUG-20260816-AAH2

Context: libgit2-global-optionsCritical / P02026-08-23Strategy: direct correction

Defect and confirmed root cause

Eleven git_libgit2_opts wrapper paths encode pointer-width size_t or ssize_t values as 32-bit ffi.Int. On a 64-bit target, getters can write eight bytes into a four-byte allocation and setters pass a mismatched variadic width.

Root-cause state: confirmed (static). The pinned libgit2 1.9.6 header was compared directly with the wrapper declarations. Native replay remains blocked because this checkout lacks generated bindings and native artifacts.

Chosen strategy

Direct correction. There is one authoritative ABI contract and no competing repair strategy. The change reuses the package's existing dart:ffi types: unsigned size_t maps to ffi.Size and signed ssize_t maps to ffi.IntPtr. It continues to import the generated lib/src/bindings.dart for libgit2 types such as git_buf and git_object_t. No hand-written aliases or new dependencies are introduced.

Boundary found during binding audit: do not route these calls through generated Libgit2.git_libgit2_opts(int option). The C API is variadic, but ffigen generated an option-only signature. The specialised wrapper remains necessary; this correction makes its declared variadic argument widths exact.

Change risk: medium. The public FFI wrapper parameter types change to reflect the native contract, which may require downstream callers to use pointer-width allocations. No broad refactor, lifecycle change, generated-binding modification, or unrelated bug fix is included.

Package closure is not attainable from this patch alone: merge and publication evidence are still required. The plan does not claim a runtime crash replay until the missing native artifacts are available.
