BUG-20260817-AAFK — Mobile native caches ignore target build inputs

Confirmed cause

Android android_api_level, iOS ios_deployment_target, and iOS openssl_target affect build flags but are missing from their toolchain fingerprints. The fingerprint is already part of both cache identity and manifest validation.

Minimal change

  1. Add a static regression test requiring each target input in its corresponding fingerprint source.
  2. Add Android API level to the Android fingerprint.
  3. Add iOS deployment and OpenSSL targets to the iOS fingerprint.
  4. Run the focused test. CI remains responsible for real cache miss/hit evidence.

Acceptance mapping

  • Changing Android API level changes fingerprint, cache key, and manifest validation input.
  • Changing either iOS target changes fingerprint, cache key, and manifest validation input.
  • The existing cache schema remains compatible; no generated or native source changes are required.

Boundary

Local validation is static because Android and iOS builds require their hosted CI toolchains. A clean cache miss and later hit must be demonstrated in GitHub Actions before package closure.
