BUG-20260817-AACM — Binding cache ignores generator contract

Confirmed cause

The bindings-cache key only fingerprints the action and manifest utility. A change to ffigen.yaml or the resolved package graph can reuse old generated bindings.

Minimal change

  1. Add a regression test that requires the cache key to hash ffigen.yaml and pubspec.lock.
  2. Extend both restore and save cache keys with those files.
  3. Run the focused test. A Linux/GitHub Actions cache-hit run remains delivery evidence, not a local prerequisite.

Acceptance mapping

  • Configuration change → ffigen.yaml changes key.
  • Resolved generator change → pubspec.lock changes key.
  • Cache behavior → restore/save keys use the same contract fingerprint.

Scope and boundary

No generated binding code, dependencies, or cache-manifest format will change. Local static regression proves the action declaration; CI is required to prove a fresh cache entry and workflow execution.
